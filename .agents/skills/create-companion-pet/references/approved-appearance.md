# Approved appearance and pilot scope

Use this guidance only when the user wants to retain an approved character while improving motion. It does not impose semi-realism on unrelated pets or replace the selected creation skill's implementation.

## Grounding and provenance

- Reuse approved full-body character art as the canonical reference; do not regenerate a base merely to begin a run. Record its actual source as reused approved art, not a newly generated result. Do not use a rejected test as the canonical reference.
- Write separate identity and rendering locks. Real photos clarify identity; approved artwork controls face and body proportions, fur, material, lighting, volume, and depth.
- Attach an approved same-state row when available. It controls pose proportions and camera angle: improving motion must not silently turn a three-quarter view into a side profile.
- For a requested style between realism and a 3D character, preserve the approved degree of cuteness and dimensional fur. Do not make the head larger or smaller, elongate the body, flatten fur, or substitute clay/plastic materials. With hatch-pet, prefer auto plus explicit style notes over forcing the smooth 3d-toy preset.
- For blink-only idle, eyelids provide the motion; keep the head, torso, wrapped tail, camera, and framing fixed.

## Pilot approval gate

- Use a separate local run folder and generate only the requested states. Typical pilots use idle and running-right; running means focused work, not locomotion.
- Defer all other state and look-direction jobs and exclude them from dispatch until the user approves the appearance. Preserve existing pets and do not install, upload, commit, or publish test media without authorization.
- Keep the selected workflow's extraction, frame alignment, shared scale, baseline, continuity, and validation checks. Correct extraction-induced changes before regenerating otherwise valid art.
- Follow the selected workflow's transparency and cleanup rules. If it permits preview-only cleanup, apply it once to a disposable copy and retain the uncleaned source for later full assembly. Never feed cleaned pilot copies into another cleanup pass.
- Show original and pilot loops side by side at native size and provide an enlarged appearance view. Report technical results separately from visual acceptance, including drift or contamination that remains visible. A numeric pass does not prove the requested appearance was preserved.
- Stop after the pilot for user review. Failed samples are evidence for revision, not approved replacement assets.
- A pilot is not an installable pet. Do not fabricate missing rows or claim full v2 validation. Complete delivery still requires every mandated state, look direction, and final quality gate in the selected workflow.
